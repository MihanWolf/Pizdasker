# AGENTS.md

Правила для агентов, работающих в этом репозитории. Читай их перед любой задачей.

## Делегирование субагенту flash

Простые задачи (`flash` на `z-ai/glm-5.3-flash`) — делегируй через Task с
`subagent_type: "flash"`, если задача подходит под **любой** пункт:

- поиск файлов, символов, использований по кодовой базе;
- ответить на точечный вопрос о существующем коде;
- правка в одном файле в одном модуле (текст, стиль, мелкая функция, тест);
- рутина: переименование, форматирование, добавление очевидной обёртки.

Себе оставляй: смену модели данных (`types.ts`), `store.ts`/`backup.ts`,
`selectors.ts`, изменения в нескольких модулях, новую функциональность,
отладку, архитектурные решения. Для них `spec.md` обязателен.

## Архитектурные принципы

1. **Никаких ручных перерисовок.** Компонент вызывает `update(draft => {...})`,
   Zustand сам уведомляет подписанные компоненты. Не тянуть состояние в локальный
   `useState` и не форсить ререндеры.
2. **Вся бизнес-логика — чистые функции** в `src/core/selectors.ts`
   (`(state, ...args) => результат`). Никаких расчётов в JSX, никакого DOM
   внутри селекторов — это даёт тестируемость без браузера.
3. **Персистентность — только через `AppState`** и один JSON. Активные элементы
   («активная страница», «активный предмет», под-вкладки) живут в `AppState` и
   переживают перезагрузку. Стор сам чинит висящие id через
   `withActiveIdFallbacks()`. Удаление ценного — через `useConfirm()`, не
   `window.confirm`.

## Команды

```bash
cd konspekt-app
npm install        # установка зависимостей
npm run dev        # dev-сервер Vite
npm run build      # tsc -b && vite build (обязан проходить без ошибок TS)
npm run preview    # предпросмотр production-сборки
npm run lint       # oxlint
npx vitest run     # прогон всех тестов
```

## Чек-лист перед сдачей

```bash
npm run build      # без ошибок TypeScript
npx vitest run     # все тесты зелёные
npm run lint       # без ошибок oxlint
npm run dev        # ручная проверка
```

- [ ] Вкладка переключается и отображается корректно.
- [ ] Данные переживают перезагрузку (F5).
- [ ] Удаление запрашивает подтверждение (кроме покупок/задач — там мгновенно,
      это осознанно).
- [ ] Экспорт → импорт не теряет данные.
- [ ] Мобильная ширина (<720px) не ломает раскладку.

## Соглашения по стилю (§13)

- **CSS-переменные** из `index.css`: `--paper`, `--card`, `--ink`, `--ink-soft`,
  `--ink-faint`, `--rule`, `--shadow`, `--teal`, `--rust`, `--plum`, `--mustard`,
  `--slate`, `--forest`, `--urgent`.
- **Шрифты:** заголовки — `'Fraunces', serif` (курсив, 600), технические
  подписи/цифры — `'JetBrains Mono', monospace`, текст — `Inter`.
- **Префикс классов модуля** (`.notes-*`, `.plants-*`, `.task-*`) — CSS глобальный.
- **Иконки** — inline SVG, `stroke="currentColor"`, `viewBox="0 0 24 24"`.
- **Без лишних комментариев** — только к неочевидной логике.
- **Иммутабельность снаружи:** внутри `update(draft => ...)` мутации допустимы
  (`push`, `filter`, присваивание) — стор сам клонирует.
- Новые динамические элементы — анимация входа (`.quote-card-enter`,
  `.watering-row-enter`, `.task-row-enter` и т.п.).
